# Aurora

**Свои люди. Свои серверы. Своя атмосфера.**

Aurora — приложение для Windows с личными сообщениями, серверами, голосовыми комнатами, видеозвонками и демонстрацией экрана. Привычное расположение панелей сочетается с собственной индиго-коралловой темой.

**Текущая версия: 1.4.1 · Windows x64 · Electron + Supabase**

> Проект активно развивается. Это самостоятельная реализация приложения для общения, а не официальный клиент Discord и не полная копия его возможностей.

## Возможности

### Общение
- Регистрация и вход по email через Supabase Auth.
- Личные сообщения, текстовые каналы и обновления сообщений через Realtime.
- Редактирование и удаление своих сообщений, ответы и реакции.
- Поиск по загруженной переписке и локальные закрепления.
- Приватные вложения до 20 МБ.

### Серверы и роли
- Создание серверов, текстовых и голосовых каналов.
- Загрузка фотографии сервера прямо при создании.
- Публичный каталог с вступлением и приватные серверы по приглашению.
- Сообщения и каналы в обоих режимах доступны только участникам.
- Пользовательские роли: название, цвет, порядок и несколько ролей на человека.
- Базовые разрешения на управление сервером, каналами, ролями и исключение участников.
- Проверка разрешений и иерархии на стороне базы данных.

### Голос и видео
- Голосовой канал с сеткой участников в центре окна.
- Управление микрофоном, наушниками, камерой и демонстрацией экрана.
- Одновременная передача камеры и экрана отдельными плитками.
- Выбор экрана или окна перед демонстрацией в Windows.
- Разворачивание плитки, полноэкранный режим и возврат к переписке без отключения звонка.

### Персонализация
- Фото профиля, имя, подпись, описание, статус и цвет обложки.
- Выбор устройств ввода/вывода и камеры, проверка микрофона и камеры.
- Настройки громкости, обработки звука, размера текста и компактного режима.
- Декоративный значок **OWNER**, назначаемый администратором базы отдельно от серверных ролей. Сам по себе значок не даёт дополнительных прав.

## Установка

1. Откройте раздел **Releases** этого репозитория.
2. Выберите опубликованный стабильный выпуск и скачайте `Aurora-Setup-<версия>-x64.exe` из его файлов — **Assets**.
3. Закройте запущенную Aurora и установите новую версию поверх старой.
4. Запустите приложение, зарегистрируйтесь и подтвердите email, если это требуется настройками сервиса.

**Рекомендуемая система:** Windows 10/11 x64.

Установщик позволяет выбрать папку и создать ярлыки. Данные приложения при обычном обновлении поверх предыдущей версии сохраняются. Перед важными изменениями собственного сервера базы данных делайте резервную копию.

> У текущего установщика нет цифровой подписи доверенного издателя, поэтому Windows SmartScreen может показать предупреждение. Скачивайте файлы только из доверенного выпуска; при наличии `SHA256SUMS.txt` проверяйте контрольную сумму. Не отключайте защиту Windows целиком.

## Что нового в 1.4.1

Небольшое обновление формы создания сервера:

- Добавлена кнопка **«Загрузить фото»**.
- Есть предпросмотр, замена и удаление выбранной фотографии до сохранения.
- Поддерживаются **JPG, PNG и WebP до 5 МБ**.
- Изображение обрезается квадратом по центру и преобразуется в WebP 512 × 512.
- После создания фотография сразу используется как иконка сервера.
- После ошибки загрузки или сохранения иконки можно повторить операцию без повторного создания уже созданного сервера в открытой форме.

**Если база уже обновлена до 1.4, для версии 1.4.1 новый SQL не нужен.**

## Первые шаги

- **«+» в полосе серверов** → создать сервер или войти по приглашению.
- **Компас** → мои серверы и публичный каталог.
- **Название сервера над каналами** → настройки, роли, участники и приглашения.
- **«Роли сервера»** → создать роль и настроить её права.
- **«Участники и роли»** → раскрыть роли у человека и назначить нужные.
- **Голосовой канал** → подключиться к разговору; кнопки камеры и демонстрации находятся внизу.
- **Шестерёнка рядом со своим именем** → профиль, аккаунт, звук, видео и оформление.

## Обновления приложения

В версии **1.4.1 автоматическое обновление ещё не подключено**. Для обновления скачайте новый установщик из Releases и запустите его после закрытия Aurora.

Интеграция GitHub Releases + `electron-updater` запланирована. Наличие файлов в Releases само по себе не включает автоматическое обновление старых клиентов: сначала потребуется вручную установить версию со встроенным механизмом обновлений.

Обновление приложения и миграции Supabase — разные операции. Необходимость обновления базы должна быть указана в примечаниях к каждому выпуску.

## Для владельца Supabase-проекта

Для работы сетевых функций необходимы настроенные **Auth, PostgreSQL, Storage и Realtime**.

- Для существующей базы Aurora до версии 1.4 используйте объединённый файл `UPDATE-SUPABASE-1.4.sql` из комплекта выпуска или исходников. Выполните его целиком в Supabase → SQL Editor.
- Полная схема `supabase/schema.sql` предназначена только для пустого проекта. **Не запускайте её поверх действующей базы.**
- Для перехода с 1.4 на 1.4.1 схема базы не меняется.
- URL и публичный anon-ключ проекта задаются при сборке. Безопасность данных должна обеспечиваться RLS и проверками серверных функций, а не секретностью anon-ключа.
- **Никогда не помещайте `service_role`, пароли, токены GitHub или ключи подписи в клиент, `VITE_*`, публичный репозиторий либо файлы выпуска.**

Настройки подтверждения email, SMTP, лимитов и резервного копирования определяет владелец Supabase-проекта.

### Публичность фотографий

Аватары и иконки хранятся по **публичным ссылкам**, в том числе у приватных серверов. Не используйте для них конфиденциальные изображения.

Переписка и вложения при этом остаются доступны только участникам соответствующего разговора. Публичный каталог показывает карточку сервера, но не открывает его историю.

## Сборка из исходников

Этот раздел относится к полному архиву исходников. Если репозиторий используется только для публикации установщиков, скачайте архив исходников из соответствующего выпуска, если он приложен.

**Требования:** Node.js 20+, npm. Для сборки установщика рекомендуется Windows x64.

1. Установите зависимости:
   ```bash
   npm ci
   ```
2. Создайте локальный `.env` по образцу `.env.example` и укажите публичные параметры своего Supabase-проекта:
   ```env
   VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
   VITE_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_KEY
   ```
3. Запустите веб-интерфейс или Electron:
   ```bash
   npm run dev
   npm run electron:dev
   ```
   Это отдельные способы запуска; одновременно выполнять обе команды не требуется.
4. Соберите Windows-установщик:
   ```bash
   npm run electron:build:win
   ```

Готовые файлы появятся в каталоге `release/`. Не включайте демо-режим при сборке сетевого приложения. Не публикуйте локальные конфигурации и секреты.

## Ограничения

- Демонстрация экрана передаёт изображение **без системного звука**.
- Звонки используют WebRTC P2P mesh и рассчитаны на небольшие комнаты. Для больших конференций потребуется SFU.
- В сборке есть STUN; для строгого NAT, корпоративных и некоторых мобильных сетей нужен отдельно настроенный **TURN**. Соединение без TURN возможно не во всех сетях.
- Пока нет полного набора разрешений Discord: индивидуальных запретов доступа к каналам, банов, ботов и других расширенных функций.
- История ограничивается объёмом загруженных сообщений; полноценная пагинация большой истории пока не реализована.
- Нет push-уведомлений в полностью закрытое приложение.
- Заявления о сквозном шифровании сообщений нет. WebRTC защищает медиатранспорт, но это не означает E2EE всей платформы.

## Проверки

Для версии **1.4.1** прошли **34 автоматических теста** интерфейса и клиентской логики, включая создание сервера с фотографией и повтор после ошибок загрузки/сохранения.

Также выполнены проверки SQL-политик и иерархии ролей для схемы 1.4, сборки Windows, версии и иконки EXE, установки обновления через Wine. Тест двух WebRTC-клиентов использует тестовые устройства Chromium и локальную замену транспорта Realtime.

Это не заменяет проверку реальных устройств Windows, настоящего Supabase Storage/Realtime и звонков через внешние сети.
